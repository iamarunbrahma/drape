# TrueHue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a live web app that reads a selfie's skin undertone/depth via YouCam APIs, classifies the user into a 12-season color palette, and virtually tries on apparel/accessories in their flattering colors.

**Architecture:** Next.js (App Router) frontend + server API routes. A pure, unit-tested color engine (`lib/color`) converts YouCam skin outputs → season → palette. A typed YouCam client (`lib/youcam`) owns the async upload→task→poll lifecycle and keeps the API key server-side. A curated brandless catalog (`lib/catalog`) is filtered by palette and fed to the try-on APIs.

**Tech Stack:** Next.js 15 (App Router, TypeScript), Tailwind CSS, Vitest for unit tests, deployed to Vercel. YouCam API v2 (S2S). Docs pulled via Context7 during build.

## Global Constraints

- **Deadline:** 2026-08-17 11:45am EDT - submission must be complete before this.
- **No third-party trademarks or copyrighted music** in any demo asset or video (Devpost rule).
- **API key never reaches the client** - all YouCam calls go through server routes.
- **Credit budget: 1,000 YouCam units.** Skin tasks ~9–12 units each; VTO per-task. Cache aggressively; validate on a small fixed set of photos; never call the API on page reload.
- **YouCam API v2 endpoint pattern:** `POST /s2s/v2.0/file/{feature}`, `POST /s2s/v2.0/task/{feature}`, `GET /s2s/v2.0/task/{feature}/{task_id}`; auth `Authorization: Bearer <key>`. Exact `{feature}` slugs, base host, and response shapes to be confirmed against the live API console in Task 1.
- **Color engine must not hard-depend on an undertone label from the API** - derive season from returned skin-tone color values.

- [ ] **Step 1: Write failing tests**

```ts
import { describe, it, expect } from 'vitest'
import { hexToRgb, rgbToLab, labHue, ita } from '../space'

describe('color space', () => {
  it('parses hex to rgb', () => {
    expect(hexToRgb('#ffffff')).toEqual({ r: 255, g: 255, b: 255 })
    expect(hexToRgb('000000')).toEqual({ r: 0, g: 0, b: 0 })
  })
  it('white -> Lab L≈100, a≈0, b≈0', () => {
    const lab = rgbToLab(hexToRgb('#ffffff'))
    expect(lab.L).toBeGreaterThan(99)
    expect(Math.abs(lab.a)).toBeLessThan(1)
    expect(Math.abs(lab.b)).toBeLessThan(1)
  })
  it('a warm golden skin has positive b* (yellow) and hue in 50-80°', () => {
    const lab = rgbToLab(hexToRgb('#e0b080'))
    expect(lab.b).toBeGreaterThan(10)
    expect(labHue(lab)).toBeGreaterThan(45)
  })
  it('ITA is higher for lighter skin', () => {
    const light = ita(rgbToLab(hexToRgb('#f0d5b8')))
    const deep = ita(rgbToLab(hexToRgb('#5a3a26')))
    expect(light).toBeGreaterThan(deep)
  })
})
```

## Task 4: Season classifier (TDD - the crown jewel)

**Deliverable:** `classifySeason` mapping skin-tone hex + Fitzpatrick → undertone/value/chroma → one of 12 seasons.

**Files:**
- Create: `lib/color/season.ts`
- Test: `lib/color/__tests__/season.test.ts`

**Interfaces:**
- Consumes: `space.ts` utilities.
- Produces:
  - `type Undertone = 'warm'|'cool'|'neutral'`
  - `type Value = 'light'|'medium'|'deep'`
  - `type Chroma = 'bright'|'muted'`
  - `type Season = 'Bright Spring'|'True Spring'|'Light Spring'|'Light Summer'|'True Summer'|'Soft Summer'|'Soft Autumn'|'True Autumn'|'Deep Autumn'|'Bright Winter'|'True Winter'|'Deep Winter'`
  - `interface SkinInput { skinToneHex: string; fitzpatrick: number /*1-6*/ }`
  - `interface SeasonResult { season: Season; undertone: Undertone; value: Value; chroma: Chroma; hue: number; ita: number }`
  - `classifyUndertone(hex: string): Undertone`
  - `classifySeason(input: SkinInput): SeasonResult`

- [ ] **Step 1: Write failing tests** (thresholds calibrated against Task 1 fixtures later)

```ts
import { describe, it, expect } from 'vitest'
import { classifyUndertone, classifySeason } from '../season'

describe('undertone', () => {
  it('golden skin -> warm', () => {
    expect(classifyUndertone('#e0b080')).toBe('warm')
  })
  it('pink/rosy skin -> cool', () => {
    expect(classifyUndertone('#e8b6b0')).toBe('cool')
  })
})

describe('season', () => {
  it('light warm skin -> a Spring', () => {
    const r = classifySeason({ skinToneHex: '#f0cfa8', fitzpatrick: 2 })
    expect(r.undertone).toBe('warm')
    expect(r.season).toContain('Spring')
  })
  it('deep cool skin -> a Winter', () => {
    const r = classifySeason({ skinToneHex: '#6b4a52', fitzpatrick: 5 })
    expect(r.undertone).toBe('cool')
    expect(r.season).toContain('Winter')
  })
  it('medium warm muted skin -> an Autumn', () => {
    const r = classifySeason({ skinToneHex: '#b98a5e', fitzpatrick: 4 })
    expect(r.season).toContain('Autumn')
  })
})
```

- [ ] **Step 2:** Run `npm test season` → FAIL.
- [ ] **Step 3: Implement `lib/color/season.ts`** - `classifyUndertone` via Lab hue angle (warm > ~55°, cool < ~48°, else neutral, with a*/b* tiebreak); `value` via Fitzpatrick (1-2 light, 3-4 medium, 5-6 deep) cross-checked with ITA; `chroma` via labChroma threshold; map (undertone,value,chroma) → Season using the 12-season table (warm→Spring/Autumn, cool→Summer/Winter; light→Light/Bright, deep→Deep/True; muted→Soft/True, bright→Bright/Clear).
